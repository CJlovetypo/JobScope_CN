# 接口健康与自修复

需要从历史表格、招聘链接及旧 API 证据定位失效原因时，使用独立的 [recruitment-link-repair](../../../recruitment-link-repair/SKILL.md)。三类原始数据、可检索索引与跨届规律已整理到 [招聘链接历史数据集](../../../recruitment-link-repair/references/history-dataset.md)。下文说明运行时自动修复的具体范围，不等于历史调查能自动修复所有平台。

采集入口默认记录接口健康。成功、正常空列表、部分分页、临时网络失败、访问受限和契约变化分别处理；不会因为暂无岗位停用来源。健康数据在共享 `state/source-health/`，为本地运行状态，不提交 Git。

仅契约变化（如 404、缺少预期 JSON 字段）触发有界恢复。单次最多读取 3 个已有公开入口、验证 3 个候选、20 次请求和 30 秒；相同配置、方向在 6 小时内不重复自动修复。限流、登录和验证码不进入参数探测。

当前自动恢复范围：

- Moka：从 `init-data` 的站点菜单或真实跳转恢复新 siteId；再次访问候选，核对 orgId、siteId 和招聘频道。多个候选无法绑定当前项目时留待复核。不通过年份替换或数字递增生成 ID。
- 飞书招聘：同一已核实租户域名的公开 website-path 变化；存在已存 tenant ID 时还需一致。跨域、跨租户不自动采用。
- 北森：读取官方入口和同域前端脚本，记录出现的新网关候选；缺少可靠租户绑定时留待复核，不自动换网关。
- 其他平台：记录失败和已有入口，保留旧契约，需要新增平台规则或人工发现。首版不承诺自动修复所有 ATS、加密协议和平台迁移。

候选必须重新取得完整 API JD，并通过上述身份和频道校验才可采用。小样本验证完成后，再按用户原来的分页和关键词范围重新采集，不能用验证样本充当全量结果。

修复对共享来源库进行加锁、读取时比较旧配置、原子写入；若其他进程已经修改配置则不覆盖。旧请求、入口、验证理由及证据路径留在 `repair_history`。三个招聘方向下次读取立即生效；新配置不能借用旧的方向与搜索能力证明。

正常空接口保留原契约。主动维护可使用 `repair-source --only 公司名`（必要时 `--force`），仍执行同样的身份与 JD 闸门；强制模式也不会探测限流或访问受限的接口。该命令不安排定时任务。

明确复核为主体错误时，沿用 `identity_verification.identity_verified=false` 保存拒绝结论。共享采集入口在发请求前返回该原因，全量与定向均适用，配置指纹变化使旧缓存失效；缺少该字段或正常空列表不会触发停用。保留来源 ID 和修复历史，只有同主体的新链路通过验收后才能恢复；不将其他公司的可用 API 作为替代。

主动维护发现不同招聘方向的官方入口时，通过同一加锁写入机制追加独立来源，保留原频道和主入口。不得用可用社招入口覆盖已关闭的校招频道。跨平台迁移需独立核实雇主；集团入口还需在请求或返回记录中保留明确的子公司边界。

已接入海南华铁官网列表（公开 source 频道和 keywords 参数）、AJINGA 列表及完整详情、IQVIA 公开页面岗位数据。AJINGA 详情同时核对岗位、频道和根公司 ID；IQVIA 严格按返回业务主体及国家筛选，属于读取公开清单后筛选，不宣称原生关键词搜索。缺失职责或要求的岗位继续标记正文不完整，招聘类型未知时不以入口名称强行补齐。

每次成功修复或追加来源会返回 keyword_review 待办信息，并在发布注册表前保存当前三个方向的配置键。接口取数恢复不是维护流程完成：主动维护必须继续运行 [定向能力验收及收尾检查](targeted-search.md#新增与修复来源的固定验收流程)。基础采集可先恢复，关键词能力未知时本地筛选；日常自动修复登记待办，不隐式启动整批维护。
