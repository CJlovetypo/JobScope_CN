# 共用匹配判断

先读[判断模型v5](assessment-v5.md)，其规则优先于旧版本说明。工作年限与相关经验分别记录为参考，不因年数差距硬否决；学历、专业单独检查。旧v4运行仅保留追溯，新prepare固定v5，不能给旧评级补版本冒充重评。

仅 discover 不做个人评级。match/compare/explore 进入正式岗位评估前，按 modes/<方向>.md 读取现有 ability-model、assessment 和 workflow 的具体结构。

资格、能力、意愿分别判断。JD 核心要求先于简历对照；标题只用于定位、资料归类或明确授权的检索，不替代完整职责、要求和招聘证据。只有真实读完才写 full_jd，程序校验不证明真实阅读。

证据分来源 kind、事实类型 claim_type、经历场景 experience_type。同一经历共用 experience_id，拆条不增加经历数量。候选人的事实陈述不冒充外部核验；本人参与不等于独立主导，团队成果不全归本人，自评只提供弱支持。按本人动作、责任、产物、反馈解释 direct/transferable/unsupported 与证据强度。

行业、团队业务、岗位职能的对口性独立分析，跨行业不自动低，同业务不自动高。先看相关性和证据质量；同等条件下实习优于学校项目，但高质量项目可支持高能力。社招核对正式责任、规模和完整交付，年限/头衔不自动评分。资格条件不得代替核心能力。

偏好只来自用户明确要求，不由经历推出喜欢；硬偏好冲突不能平均抵消，关键供给未知不评高。不确定的是哪一条件要说明。资格冲突、能力低或意愿冲突导致 hold；资格/意愿未知不能 apply。新运行使用[v5完整规则](assessment-v5.md)：缺证unknown，能力低需要已证实核心冲突；关键事实未知且无明确冲突时clarify，未知是有效完成。城市、薪资参考和证据充分性独立展示，不重复进入工作内容意愿；不新增百分比分数或录用概率。

当前画像整体指纹变化使旧评估失效；复用原事实和JD后重新判断，不给旧结果补指纹。report_summary 保留结论、能力、意愿、缺口四段，准确而易读，不能为了好看删去资格冲突或实际限制。
