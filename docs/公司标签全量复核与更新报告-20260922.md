“采集完整”表示本次来源采集器返回完整覆盖；“索引完整覆盖”还要求目标招聘方向、岗位开放状态和地点证据满足写入标准，两者口径不同。部分覆盖只补充观察到的城市，不删除历史城市；失败不清空旧标签。三个方向各有 2335 家复用 2026-09-19 且来源配置指纹未变化的结果，885 家于 2026-09-22 重新采集。失败主要为招聘系统 HTTP 429、超时、403、公开接口结构变化或解密配置失效；立即重试会放大限流，因此本轮保留失败状态和旧城市。

原始逐主体结果与失败原因分别保存在三个方向的 `artifacts/city-refresh-20260919/summary.json`。为解决刷新期间磁盘空间耗尽，本轮删除了可再生成的 HTTP 响应缓存；正式索引、逐公司 `result.json`、`summary.json` 和总汇总均保留。新增 `prune-city-refresh-cache.mjs` 只允许删除三个已知方向刷新目录下、非符号链接的 `http` 子目录。

## 业务与行业边界

业务和行业没有进行无证据批量补齐。现有 2695 家行业路由缺逐主体业务依据，2009 家业务结论为部分证据，890 家缺业务标签；本轮已逐公司记录这些状态，没有把“尚未证明”写成 verified。现有行业体系的分类迁移、新业务词映射和来源优先级仍属于需先审核的规则变更。

后续补证可直接以最终复核台账为队列：优先处理 `ownership.evidence_missing`、`business.evidence_missing`，再处理 `business.partial_evidence` 和 `industry.current_routing_retained`。补证过程是独立维护任务，不进入求职用户的搜索、匹配和报告流程。
