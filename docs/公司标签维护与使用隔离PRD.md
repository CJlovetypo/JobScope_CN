# 公司标签维护与使用隔离 PRD

日期：2026-09-22。状态：本轮流程隔离、维护入口与分类证据标准已实施，离线回归通过。依据：用户确认“用户使用过程默认标签都是 OK 的，数据信息更新只作为主动触发流程，不在主要产品体验中”。验收见 [测试报告](公司标签维护与使用隔离测试报告.md)。

## 目标与边界

公司性质、行业、业务属于稳定知识，核实后固定复用；招聘城市属于随岗位变化的索引，可更频繁维护。两类数据均只在明确触发维护时更新。普通岗位搜索、匹配、比较、报告与岗位雷达消费已保存数据，不自动初始化、刷新、重新调查或回写共享标签，不向求职用户索要维护决策。

正常 collect / collect --refresh 仍取得本次所需的岗位与 JD；“找最新岗位”不等于“更新公司标签”。本轮不创建定时维护，不运行全库网络刷新，不批量重标正式公司。本轮实现流程隔离、维护入口、分类与证据标准及离线盘点；不擅自更换现有行业枚举或公司性质来源优先级。重新划分行业和批量标签迁移先提交具体映射供审核。

## 已确认规则

1. 搜索直接使用当前方向城市索引，包括首次运行，不因索引旧、缺失或来源配置改变自动刷新。现有城市硬筛语义保留：指定城市未命中则排除，未指定城市不因此排除；索引缺失按未记录处理，不跨方向借用城市。不将未记录解释为公司确定没有该城市岗位。
2. 公司性质、业务等缺项按现状显示待核实/暂无资料，不阻止岗位采集或报告导出；不得为了继续而造 verified。维护层严格证据校验保留，使用层不重新做事实核验。
3. 每次 prepare 固定本轮公司标签和资料快照，旧报告不因共享数据后续维护静默变化。
4. 城市维护按招聘主体和 campus/internship/social 隔离。完整采集且岗位方向、开放状态和地点明确时更新当前集合；失败保留历史，部分覆盖只补充不以未看到为由删除。定向关键词结果不替代全量城市索引。
5. 主动维护只更新指定字段及范围，保留证据、时间、覆盖与历史。公司性质继续采用现有供应商结构化字段优先、Waiqi 补充规则；主体冲突、合资等不强行归类。

## 架构与执行

- 使用入口：job-search 及三个兼容方向入口；catalog → prepare → collect → 评估 → render 只读取公司基础数据。
- 维护入口：shared/job-search-core/scripts/company-maintenance.mjs；audit 只读盘点，cities 显式调用既有方向刷新，ownership 显式调用既有维护器（默认预览，--apply 写入）。业务与行业资料按维护标准整理证据后定向维护，不用关键词全库重标。
- 分类与证据规则：shared/job-search-core/references/company-label-model.md；行业用于宽类范围，业务描述产品/服务，性质描述主体属性；岗位职能独立，集团业务不能直接替代团队或子公司事实。
- 独立维护任务才读取 maintenance.md，主流程不把维护缺口列为下一步必须操作。

## 验收

- 三方向 catalog/prepare 在城市索引缺失、过期、配置指纹变化的情况下均不发网络请求或写标签；城市硬筛结果遵守现有规则。
- 性质缺失/unknown 可进入匹配并导出报告，unknown 不升级为 verified；已有 verified 结论原样使用。
- collect 获取本次岗位后不回写共享性质、行业、业务和方向城市索引。
- 主动城市维护仍可更新指定方向且保留失败/部分覆盖历史；主动性质维护保留预览、备份和原有来源优先级。
- 盘点输出保留分类词表、依据缺口与覆盖状态，不修改正式数据。
- 运行相关自动回归与 Skill 结构验证。网络维护测试使用隔离副本和模拟响应；不能声称全来源实时有效。

## 后续审核事项

现有行业目录混有经济活动、产品与供应链位置，不在本轮自动归并。后续分类迁移需提交新旧分类映射、受影响公司与搜索范围变化供用户审核。维护频率由主动维护任务决定，本轮不设隐含有效期或自动调度。
