# 匹配判断模型迭代审核稿

追加确认：工作年限默认作为经验参考，单独记录JD年限与已知经验差距；结合实际职责、责任深度和成果判断放宽依据。缺证不确定，不因年数不足直接否决，不声称雇主一定接受，不设置统一“可少几年”的阈值。原“4对6年”的事实差距保留，但不再作为硬性资格否决。

日期：2026-09-22。状态：用户已批准R1–R7，并已单独确认工作年限弹性规则。下文保留审核时的问题和示例；当前实施定义见[匹配判断模型v5迭代PRD](匹配判断模型v5迭代PRD.md)，年限示例以新增确认覆盖。

本稿对应用户最新要求，取代上一条需求中“薪资完全忽略”的拟议处理。上一轮中断时写入的局部规则已撤回到此前架构迭代基线，避免不完整的新旧规则混用。原业务 PRD 的已完成状态及 100 例验收只代表此前版本，不代表本稿已经落地或通过验收。

## 1. 用户已明确的方向

1. 地点仅匹配城市意愿，不支持同城远近、离家距离或通勤时长。最终评估增加城市意愿维度。
2. JD 返回的薪资可能不准确，须明确向用户说明“仅供参考，不代表实际可获待遇”。最终评估增加薪资参考维度，影响权重很低。
3. 用户没有提供某项能力证据，应为不确定，不能直接判不匹配。没有简历文件也不能等同于没有能力；已经给出的具体文字经历可以作为证据。
4. 额外业务规则先 review 后实施。本稿下述状态定义、汇总逻辑、排序方式及流程调整均作为具体待审方案。

## 3. 待审规则清单

### R1：缺证与明确不符分开

当前：unsupported/none容易流向能力低，再流向拒绝建议。

建议对每项要求保留两个独立判断：

| 判断 | 可用状态 | 含义 |
| --- | --- | --- |
| 要求是否符合 | 符合、部分符合、明确不符、不确定 | 比较JD要求与用户事实的结论 |
| 证据支持方式 | 直接、可迁移、未提供；另标强/中/弱/无 | 说明结论从何而来，不把无证据当零能力 |

- “材料没写预算预测”→不确定。
- “用户明确说从未独立做预测，JD要求入职即可独立负责预测”→该具体要求有明确缺口，不能扩大成所有财务能力低。
- 已给具体相关行动与成果→可判断直接或可迁移支持，不要求一定上传简历文件，不要求必须有外部证明或量化数字。
- 自称“英语很好/擅长分析”→保留为自述线索，尚缺使用情境时不夸大为强证据，也不因此判能力低。
- 资格判断同样适用：未提供证书/相关经历→未知；明确无必需证书、总年限明确少于最低门槛→冲突。

“不确定”可与已证实的具体冲突同时存在，分别展示；不能因为有未知就覆盖已知冲突，也不能因为一处冲突就把全部维度判低。

影响：修改三个方向的判断说明、证据结构与校验器；为低匹配/明确不符保存具体事实依据。旧 unsupported 不自动批量改为正向结论，要重新理解原事实。

### R2：不确定是可保存、可交付的判断结果

当前：程序把“完成阅读后仍无法判断”与“尚未执行评估”混在一起。

建议拆开评估进度与匹配结论：

- 未处理：尚未阅读全文、未做对照。
- 已审阅、待补资料：已处理可用资料，关键事实不足，保留不确定及具体待补项。
- 已审阅、有可判断结论：包括符合、有条件符合、明确不符。

有真实阅读/对照及缺项依据的“不确定”允许提交、合并、导出；不在资料未变化时无限重跑。正文抓取失败仍属于资料不足，不能假装完成全文判断。补新事实或JD变更后再触发相应重评。

没有画像时可继续岗位发现、JD要求拆解和已知偏好对照，能力保持未知；有简略文字画像时只评可判断维度。不能为了通过 prepare/批次校验编造履历。用户应看到“已审阅58岗，其中多少项仍待资料”，而不是“58岗均已确认适合性”。

影响：不仅改SKILL，还需改准备条件、批次状态、缓存/重试条件、结果接受规则和报告分区。保留现有部分报告的完整性约定，但明确“范围已审阅”与“全部结论已确定”的差别。

### R3：城市单独评估，同城距离不进入目标

建议状态：符合、部分符合、不符、不确定、未指定、不限制。地点事实与用户意愿分栏，未知不写成不符；总部地址不替代岗位工作城市。多地点岗位若能在目标城市任选则符合，只有需多地到岗/轮换等事实限制时才可能部分符合或未知。

- 用户“只看上海”：保留已有明确城市范围约束，明确北京岗位不纳入该范围。
- 用户“最好上海、杭州也能考虑”：按明确范围及偏好强弱判断，不把上海偏好自动升级为只上海。
- 用户未指定城市：本轮不按城市收窄，状态“未指定”，不冒称其明确不限。
- 用户明确不限：状态“不限制”，不作为额外加分。
- 无城市限制且岗位城市未知：地点显示未知，建议不阻断能力/资格等其他维度；有城市限制时，只将城市维度标未知，不能声称满足。
- “半小时通勤/离家近”明确告知不支持并忽略，不追问地址、距离或交通方式，不留作后续工作。

影响：新增最终城市意愿字段；避免又在普通意愿里重复计入城市。需调整未知城市导致整岗停评的规则。公司城市标签的既有硬筛可能漏掉资料不足来源，本稿只提出披露与独立判断，不默许扩大搜索范围或全面废除公司准入政策；若要改公司级硬筛，另行审核。

### R4：薪资为独立、低影响的参考维度

建议在用户提出薪资要求及报告薪资字段旁明确提示：**“招聘信息中的薪资可能不准确，仅供参考，不代表实际录用待遇；不按薪资硬筛岗位。”**

用户已经提供的薪资偏好可以记录作参考，不主动将薪资问题设为前置必填。只在JD披露与用户要求口径可比较时，给出“表面相符/部分重合/存在差距”的参考结果；未披露、月薪与年包等口径不明、固定薪酬与奖金构成不明时，标“未知/不可比”。不编造薪数、奖金、换算结果、缺失薪资或实际可谈空间。仅有宽泛“涨一些”时不追问当前收入来完成非必要评分。

**低权重建议采用：只在资格、能力、主要意愿与城市判断相当时影响辅助排序，不改变主要匹配档位，不单独触发“不匹配/暂不建议投递”。** 本包当前没有总分模型，先不引入未经校准的百分比。若需要薪资参与数值总分，应另审计分方式和影响上限。

用户说薪资必须达到某值时，也不能谎称系统能保证；告知仍只参考，不用不可靠区间直接删除候选。薪资未知是无可靠参考，不扣分，也不默认为达到预期。用户没给偏好时只展示原值，不创建偏好。

影响：与上一轮“完全忽略薪资”不同，保留参考维度但不做可靠性不足的硬筛。检查 salary/salary_raw/raw_metadata 等已有返回值，保留原文和来源日期；本稿不授权扩大采集或推算实际薪酬。

### R5：主要结论、行动和证据充分性一致

建议最终展示六个独立维度：硬性条件、能力、工作内容等意愿、城市意愿、薪资参考、证据充分性。最后一个说明哪些判断可靠、哪些缺事实，不作为能力分。

| 情形 | 总体表达 | 行动 |
| --- | --- | --- |
| 存在已证实的硬性资格或明确不可接受条件冲突 | 明确不符，并列出冲突 | 暂不建议投递；其他未知仍保留 |
| 没有明确冲突，但关键能力/资格缺事实 | 信息待确认；可保留为候选 | 补资料后判断，不写成能力低 |
| 主要条件有足够支持，但存在可迁移或准备要求 | 有条件匹配 | 针对性准备 |
| 主要条件有足够直接支持且无重要冲突 | 匹配依据较充分 | 可以考虑投递，不承诺录用 |
| 仅薪资参考存在差距/未披露 | 主判断沿用其他维度 | 提示参考差异，不单独否决 |

关键能力不足时不直接建议“可以投递”；但“暂不能判断”也不应伪装为“暂不建议”。建议增加清晰的“补资料后判断”动作，避免沿用“投递前准备”暗示已经确定适合。每一行的总体结论、投递动作及解释需相互一致，防止第32、36行这类表述冲突。

影响：汇总矩阵、动作校验、标签与Excel同时修改。拟保留四页签，现有列新增“城市意愿匹配”“薪资参考”“证据充分性”三列；薪资原值和参考判断放同一参考单元格，不能只显示一个无法解释的薪资分。表头变化及固定列数测试须一起更新。

### R6：区分学历、专业、总年限和相关经验

当前部分规则把学历与专业混在一个 degree 检查中，把总工作年限与具体行业/职能年限混在 employment_years 中。

建议保留各自事实：已知硕士不应显示“学历未知”，财务相关专业未提供可单独未知；4年总经验与JD的6年参考存在差距，但不直接否决，也不能证明没有预算/经营分析工作；需看实际责任、成果及放宽依据。JD“优先、有更好”不得升级为必需。领域邻接或职级名称只能提示需要核实的实际职责，不直接构成不匹配。

影响：拆分检查字段或增加同一字段下的子条件，保持“任一已证实硬冲突决定资格不符、未知不制造冲突”的规则。校招、实习、社招采用同样的事实区分，但保留各自真实资格项。

### R7：补问按任务聚合，只问改变结论的信息

本报告大量岗位缺的是同一类个人信息。建议在判断发现画像不足时，聚合高频决定性缺项，一次优先问不超过3组，如“预算预测/管理报告具体做过哪些”“独立负责范围与业务协作”“JD确实要求的资格或相关年限”。不对58个岗位重复问58遍，不要求上传全量简历才能继续，不问同城通勤，也不为薪资参考阻塞执行。

用户只想先看机会时，交付保留未知的候选。用户补充新事实后保留旧报告并重新评估，不能只把旧评级换标签/指纹。本轮仍采用既有画像整体变更后重评规则，不额外引入未经审核的逐维度缓存算法。
