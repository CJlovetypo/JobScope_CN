## 1. 问题与目标

当前三类匹配 Skill 共用采集代码，但意图识别、补问、检索策略和交付流程散落在各入口。岗位发现被画像前置条件绑定，未指定与明确不限缺少独立记录。用户已经说清的条件容易再次询问，采集范围、评估范围和执行批次容易混淆。

本轮交付一个主要求职入口、共享业务决策规则、按方向加载的差异规则，以及可执行的任务记录与验证工具。保留已有方向 CLI、来源库、匹配证据模型、Excel 和雷达/修复独立任务。自然语言由 Agent 理解；程序校验决策契约，不新增用关键词冒充意图理解的分类器。

## 2. 架构与职责

- `job-search/SKILL.md`：任务识别、按需加载、继续/澄清/交付的入口；不是常驻服务或独立 Agent。
- `shared/job-search-core/references/decision-policy.md`：唯一通用决策规则，定义意图状态、澄清、约束、变化与边界。
- `search-strategy.md`、`matching-model.md`、`delivery.md`、`modes/*.md`：策略、共用判断、交付及招聘方向差异。
- `job-search/scripts/jobs.mjs`：统一 CLI，显式方向启动独立旧运行上下文；任务检查/保存不采集网络。
- 共享代码：校验任务与执行输入的一致性、保留任务快照；增加无需画像的岗位发现分支和独立发现交付。
- 三个旧 Skill：兼容入口，给出已选方向，使用同一组决策规则；旧命令仍可运行。
- `job-radar`、`recruitment-link-repair`：独立生命周期，复用规则，但保留各自调度、历史与修复权限。

## 3. 产品规则

### 3.1 意图和信息状态

任务分为 consult（资格/材料/使用咨询）、capabilities、discover、match、compare、explore、radar、repair；多个任务指代未明时用 clarify 保留未决状态，不擅自选一个分支。招聘类型明确则不重问；校招身份不能由“没交社保”直接推出，PM 等歧义保留。方向入口视为方向线索；用户明确改方向时以本轮意图为准。

条件分别记录状态（explicit/inherited/unspecified/conflict）、值及依据。城市未提及默认本轮不设城市过滤，仍记录 unspecified；与用户明确不限区分。不能以所在地、学校或工作经历推断意向。行业未指定要补问，不自动全行业；直接指定公司可限定这些公司，直接比较给定岗位无需再问全市场行业。厂级、性质、业务、职能、办公方式分别记录。

### 3.2 阶段与澄清

功能咨询先回答能力。岗位发现需要明确招聘方向和公司/行业范围，不需要简历、学历或评估数量。个人匹配需要真实经历和方向必需画像，范围可以采集后确定；缺材料可先整理条件、读已有资料、解释行业、定位目标。每轮优先最多 3 组高价值问题，未问的缺口保留，不用长表堵住全部工作。

缺少附件/历史/截图时不声称已读；尝试定位已有材料，不能为测试虚构文件。可用脱敏经历，不要求姓名电话、详细住址或客户机密。自评、团队成果、参与/主导分别处理。前 010 例给出的文字经历已经是材料，不再要求简历文件。

### 3.3 策略、范围与完整性

普通岗位目标默认 exhaustive，仅明确接受快速标题定向时用 targeted。保留现有标题近义词依据、候选公司依据、原生查询能力证明和遗漏披露。目标职能可用于全文后的候选解释或意愿判断，不能暗中变成标题硬过滤。采集全量、评估全量、批次大小分别保存。

评估范围明确时直接继承；未明确时在筛选后询问。`前N个`固定展示顺序岗位键；`最适合N个`不等于抽样N个；`剩下全部`只指当前已确定范围。零命中不暗中扩词/扩公司；先区分失败、部分覆盖、真实空、筛选排除。

保持现有公司城市标签硬筛政策，披露“当前标签未命中”和缓存日期，不宣称无招聘；不跨招聘方向借用城市证据。本轮不改变来源库与城市准入策略。公司性质补核仍是正式匹配准备条件；纯岗位发现不因公司背景资料缺失而阻塞。

### 3.4 变更和完成

城市/行业扩展补查新增范围，默认保留旧报告；明确最新时刷新。经历或偏好变化建立新运行并使旧评估失效，不重新索要未变化的材料；允许复用相同方向/来源/检索范围的 JD。当前仍保守地重评完整画像变化，不引入未经验证的细粒度评级复用。

所选可评估范围完成才称完整评估；用户要求提前交付才允许部分报告。样本数不是全库推荐前N名。发现结果只称候选，不能称个人适合或可以投递。岗位雷达只在宿主确认后称启用，暂停与静音须区分；模拟验收不真实创建订阅、发送消息或改正式来源。

## 4. 任务记录与运行契约

任务记录包含 schema_version、task_id、revision、user_request、goal、is_test、conditions（状态/值/依据）、retrieval（模式/选择依据）、evaluation_scope、materials、issues、changes。保存修订时继承未改变的明确条件，记录 supersedes；文件不可覆盖。派生结果包含目标入口、需要补问的条件、可先推进的动作、阶段阻塞、刷新/重评要求。

主入口的 prepare 必须绑定通过校验的任务记录；方向、行业、城市、公司及定向策略不能与记录矛盾。程序无法证明自然语言提取和语义判断正确，需行为验收。旧运行与旧 CLI 不强制补造任务，历史报告继续可读。

discover 允许空经历；collect 继续使用现有采集、范围与证据逻辑。发现分支只能交付候选清单和来源覆盖，不进入 batch/个人评级/匹配 Excel；切换匹配需补真实画像并新建运行。匹配交付仍为现有四页签 Excel。

## 5. 验收

1. 100 条提示词按真实原文与给定上下文做独立首轮模拟，观察点不作为用户输入；逐条保存首轮回应、已知条件、补问、可推进动作、问题及修订复测。
2. 未提供的附件、岗位、订阅等列为待取得；对应路径只验证首轮处理，不能标成完成真实匹配或调度。
3. 契约测试验证方向/条件不重复补问、阶段阻塞、默认策略、继承和更正、显式定向依据、不可覆盖历史、输入与任务一致性。
4. CLI 链路测试覆盖主入口及三个兼容入口，发现 prepare/缓存 collect/交付和正式评估隔离；沿用既有匹配、方向、范围、雷达、修复测试并真实生成/打开 Excel。
5. 测试区分行为模拟、离线/合成执行链路、真实联网验证。不得把单元测试、预设期望或人工自评写成100条真实在线任务成功。
6. 不保证第三方接口永久可用或全市场无遗漏；本轮保证已验证路径的规则一致、缺失和失败可解释。性能通过不重复索要信息、按需读规则、先本地校验再联网、复用合规缓存实现，不以隐藏缩小范围提速。

## 6. 实施顺序

先写共享规则与入口，再实现任务契约/统一 CLI/发现分支，随后独立100例模拟及执行回归，最后修订问题并提交本地测试报告。保留旧入口和数据，不部署、不自动投递、不建立真实定时任务、不批量改源。
