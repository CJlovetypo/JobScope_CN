# 公司标签维护与使用隔离测试报告

日期：2026-09-22。对应 [PRD](公司标签维护与使用隔离PRD.md)。

## 实施结果

- 移除 catalog/prepare 的城市首次初始化；城市索引缺失按现有未命中规则处理，不触发联网或要求求职用户先维护。
- 移除 prepare/render 的公司性质维护前置条件。已保存 verified 标签直接使用，unknown/缺失显示待核实，状态与依据保留；不会伪造核实结论。批次材料同时带性质状态。
- 公司简介缺少合规资料时保留原记录供追溯，展示暂无已核实资料，不使求职流程转入资料调查。维护时的严格字段和证据校验保留。
- 新增主动维护入口 company-maintenance.mjs：只读 audit、指定方向 cities、供应商/Waiqi 性质维护（默认预览）。城市刷新保存旧索引；失败和部分覆盖仍沿用保留历史规则。
- 新增公司标签模型，整理行业/业务/性质/招聘城市的维度、主体口径、证据来源和更新边界；保持现有行业ID及性质来源优先级。
- 更新统一入口、三方向兼容入口、工作流、维护说明与 README 的相关表述。

## 验证结果

完整 Node 回归 **440/440 通过，0失败，0跳过**，约26.18秒。含既有匹配v5、报告/Excel生成与读取、来源采集器、城市历史保留、性质维护器、岗位雷达与链接历史测试。

命令：

```sh
node --test job-search/runtime/campus/scripts/tests/*.test.mjs job-radar/scripts/tests/radar.test.mjs recruitment-link-repair/scripts/history.test.mjs
```

新增维护测试共2项，其中隔离执行测试依次运行三方向真实CLI。测试复制运行代码到独立目录，仅在副本替换招聘采集器为确定性合成响应，禁用真实 fetch，不修改生产源文件。验证：

1. 缺城市索引、过期索引、旧配置指纹时，catalog/prepare 无采集调用；指定上海按旧索引选取，不因已过期改结果。无索引且未指定城市时仍能入选。
2. 缺公司性质和无合规依据的简介不阻止 prepare；unknown 保持未知，原资料保留在快照。
3. collect --refresh 获得深圳合成岗位，但共享性质/业务/行业/城市文件字节不变。
4. 显式 cities 维护才将对应方向城市改为深圳，留下上海旧索引备份；既有运行快照仍保留上海。其他基础标签文件字节不变。
5. audit 不修改输入，拒绝覆盖已有输出；拒绝向 audit 传 apply，城市维护必须明确方向，不能额外按旧城市过滤公司。

完整回归后进一步扩充上述同一隔离测试的“未指定城市”和“无效简介保留原始记录”断言，定向重跑 **2/2 通过**。4个修改的 Skill 均通过 quick_validate。性质入口 supplier 预览实际运行成功，apply=false，正式性质记录变化为0。

## 覆盖边界

本轮未刷新正式城市索引、未批量修改公司标签、未创建维护调度。正式来源和公司数据目录无 Git 差异。网络维护能力由既有离线采集器测试与合成CLI链路验证，不宣称所有线上接口当前可用。行业重分类与业务词表批量归并需先提交具体映射审核，本轮未执行。

README 已按使用与维护分离更新相应说明。本轮未推送 GitHub，未读取或修改 GitHub About；推送前仍须按仓库规则单独检查。
