# 公司画像分层与独立联网复核 PRD

版本：2026-09-23。依据：用户确认身份、标签、描述、治理分层，并要求底层适配后，对全部已存公司逐一重新联网判断。

## 目标与范围

以 company_id 为稳定主键，提供统一公司画像读取接口。身份信息、受控标签、自由描述、证据治理分别表达；招聘入口作为来源元数据保留。校招、实习、社招城市分别保存。存量数据迁移与事实复核是两个独立进度，迁移成功不代表已经重新联网核实。

日常求职离线读取已发布结论，不触发标签搜索、自动刷新、过期阻断或向求职者发起维护问题。准备运行时固定画像快照；后续维护不改写历史运行。

## 数据契约

| 分区 | 字段 | 口径 |
| --- | --- | --- |
| identity | company_id、display_name、aliases | 招聘主体的身份锚点；不能仅靠同名合并 |
| tags | industry、business、ownership、organization_size | 行业采用现有19类ID；业务沿用现有词表；性质及规模沿用已批准模型 |
| tags | headquarters_country、listing_status | 预留已讨论维度；缺少可核实值时为 null，不推断；国家原文保留，当前不新增硬筛选规则 |
| tags.recruitment | campus/internship/social.cities | 本次官方开放岗位的地点；各方向独立，非公司办公地点 |
| descriptions | business_summary、products_services、customers、business_regions、workforce、capital、entity_relationships | 自由事实描述；人数需主体范围与统计时点；集团事实不自动套子公司 |
| governance.fields | 每个字段的状态、理由、主体口径、统计时间、核实时间、证据、来源方式、重新复核状态 | 覆盖率属于治理，不属于公司业务标签 |
| governance.recruitment | 三方向覆盖状态、刷新记录、岗位证据、配置指纹 | 区分完整空、部分空、失败；只说明已收录来源覆盖范围 |
| sources | 招聘系统、入口、身份核验、接口来源 | 技术元数据，与公司属性分开 |

不新增行业分类、规模阈值或所有制推断规则。公司是否上市与公司性质分开；总部地址本身不证明控制关系。未知值不得伪装成结论，not_disclosed 也需要核查依据。

## 存储与读写

1. 已有主档、业务、性质、简介、城市数据继续作为存量兼容输入；迁移保留原始值及出处，不由旧字段生成新的核实结论。
2. 新增统一画像构建层和正式复核覆盖层 company-label-reviews.json。每个字段独立覆盖，未复核字段明确为 pending，不计入本次完成数。
3. 维护导出 company-records.json，供逐公司检查；使用层从当前兼容输入和已发布复核结论组装同构画像，防止导出物陈旧。
4. catalog/prepare 使用统一适配结果，prepare 保存 company-records.snapshot.json。公司简介读取同一轮复核描述；规模根据当前性质和人数按既有模型派生，避免旧性质残留。
5. 普通采集不回写标签；仅显式维护发布新结论。发布文件原子替换，保存旧版本备份。

## 独立联网复核

- 清单覆盖注册库的全部 company_id，包括原来 verified 的公司。不能仅搜索缺失项。
- 给研究者的队列只包含公司ID、名称、别名、招聘入口等身份线索，不包含旧行业、业务、性质或人数结论。
- 每个公司保存本轮查询词、实际检索时间、工具、结果URL，以及已读取正文的证据摘录、正文哈希、读取时间、公开时间（如有）、主体关联说明。
- 本轮旧资料只能作为检索定位线索；旧标签及旧“verified”状态不能作为新结论依据。可以重新打开同一个官方来源，但必须保存本轮读取记录。
- 每个判断引用本轮正文证据。程序检查ID、时间、引用和词表，Agent负责判断证据是否实质支持该结论。搜索摘要不是已读正文；HTTP成功不代表核实成功。
- 检索失败、正文不可读、同名无法确认分别记录；不强制给出标签。仅搜过、仅下载、部分字段完成、全部字段复核分别计数。
- 城市另走本轮官方岗位新采集，不用旧缓存或官网办公地址代替；完整覆盖范围限定为维护的招聘入口。部分/失败保留历史集合，但历史城市不计本轮新证据。
- 宽行业无法确定或涉及分类规则调整，留待审核，不新增分类推断。

## 验收

- 全部注册公司可生成四层画像，唯一ID和来源记录不丢失。
- 迁移不增加任何 fresh_review 完成数；队列不含旧标签。
- 拒绝引用其他公司、旧批次、未读正文、无证据或越过词表的结论。
- 独立修改某一维度不会清空其他字段；描述更新与报告同步，旧运行快照固定。
- 三方向求职入口、公司筛选、匹配及Excel交付回归通过，过程不产生标签维护网络请求。
- 全量复核完成的必要条件：每家完成本轮检索与主体核对、全部静态字段复核（允许有证据的未决）、三方向城市新采集有记录；报告必须分别列出已完成与未完成数。建立队列或结构迁移不能宣称全量复核完成。

## 交付与进度

交付包括本PRD、统一画像模块、维护CLI、兼容读取适配、回归测试、全量逐公司复核队列和本轮证据。当前实际进度由维护CLI status生成，不能手写一个“全部完成”的计数。
