## 交付内容

- 新增 `job-search` 统一入口，按任务和招聘方向读取共享规则；原三个方向入口继续可用，雷达和来源修复仍是独立任务。
- 共享业务规则区分任务识别、条件状态、必要补问、检索策略、评估范围、变化处理和交付要求。
- 增加任务检查、不可覆盖修订、历史继承、执行参数绑定和评估范围校验。新入口不会默认把未知招聘方向当校招。
- 岗位发现可无简历启动，输出明确“尚未个人匹配”的 Markdown/JSON；个人匹配仍要求真实经历、完整 JD、明确范围并输出原四页签 Excel。
- 不通过给旧结论更换指纹复用评级；变更后的任务保留历史，符合契约的JD可复用。

政策依据及确认记录见 [PRD](求职元能力架构迭代PRD.md)。四项已确认政策：未指定城市本轮不筛、指定公司免行业补问、语境明确的整体开放可解释为不限并告知、每轮最多3组关键问题且不能塞长问卷。

## 执行回归

本轮完整 Node 回归：**423项通过，0失败，0跳过**。日志：[执行回归](../job-search/artifacts/validation/regression-final.log)。此轮约21.37秒，包含并发离线测试，不能作为真实招聘来源采集耗时。

已验证的实际代码路径包括：

- 统一入口方向选择与原三个CLI兼容；合成查询在三个招聘方向均完成 prepare → 有效快照 collect → 候选报告落盘。
- 缺简历不阻止发现；发现运行不能创建正式匹配批次或渲染匹配Excel。
- 输入条件与任务不一致、任务快照改动、画像指纹变化等被阻止；任务修订保留未改变事实和未解决问题。
- 已明确范围不重复问；全量、样本数量、指定公司及前N固定岗位键的约束；范围修订保留任务历史。
- 补测并修复两处命令约束：母集充足时不能少传样本岗位；不能用 --only 绕过任务记录缩小抽样公司。真实母集不足仍可按实际数量交付；等价JSON属性换序不误判为材料变化。
- 既有采集器、方向识别、正文完整性、分页/失败处理、城市/公司标签、证据引用和缓存失效测试。
- 实际生成 Excel，重新打开校验工作表、列、长文本、链接和公式文本处理；雷达SQLite持久化与变化状态、历史链接解析也通过。

六个 Skill 的结构验证通过。Windows 默认GBK导致校验脚本首次读取中文失败，使用 Python `-X utf8` 后六个全部通过；没有修改用户全局编码或校验器。`git diff --check` 未发现空白错误。

额外独立执行了23个离线CLI探针，发现的两处范围约束漏洞已修复并复测：22项具有明确预期的检查符合预期，另1项未定义选项语义的探索记录不计验收。子进程禁止网络，输入为合成任务；首次失败记录和修复后记录分别保留。证据：[命令复测摘要](../job-search/artifacts/cli-forward-agent-20260922/retest-summary.json)。这些检查不计入上面的423项自动回归。

## 覆盖边界

100例是首轮行为模拟和模型交叉评审，**不是100次真实在线求职任务**。案例中的附件、旧报告、JD和调度结果未实际提供，因此没有伪造这些材料或声称完成真实投递/调度。初轮输入包含场景标题；交叉复核和复测明确只以用户原话及前置上下文作为依据。后续输入导出已支持移除标题和观察点。

执行回归使用合成材料、模拟响应或有效快照；本轮未进行全来源实时联网巡检，不能据此保证第三方接口持续可用、全市场无遗漏或任意自然语言输入都正确。未建立真实订阅、未发送外部消息、未修改正式招聘来源。岗位判断仍需Agent真正阅读全文，结构校验无法证明语义判断质量。
