# Job Search Skill Pack

按行业和城市筛选公司、逐岗评估的求职 Skill 集合。

把分散在公司招聘站的已开放校招岗位汇集起来，在你确认的范围内逐一阅读、逐一评估，找到与你的经历和求职意愿相符的机会。

你提供简历和方向，skill 帮你遍历岗位、对照要求，最后交付一份有理由、有原文链接的投递清单。

## 选择招聘方向

| 方向 | Skill | 额外需要的个人信息 |
| --- | --- | --- |
| 应届正式校招 | [internet-campus-job-fit](internet-campus-job-fit/SKILL.md) | 学历、毕业时间 |
| 实习 | [internship-job-fit](internship-job-fit/SKILL.md) | 在校状态、预计毕业时间、可开始日期、每周天数、持续月数 |
| 社招 | [social-job-fit](social-job-fit/SKILL.md) | 学历、正式工作年限、具体工作责任与成果，及明确的到岗与薪资偏好 |

三者沿用同一体验：输入简历与倾向，选择行业和城市，查看采集范围并确认评估范围，逐岗阅读完整 JD，交付四页签 Excel。各自独立保存城市标签、运行与评级；实习和社招不会直接拿校招城市标签做硬性排除。个人条件尚未提供时如实标待确认，不编造年限或实习安排。

三个 skill 直接使用同一份 [API 来源库](shared/job-search-core/assets/sources.json)、公共采集器和公司事实资料；更新一次，三个入口立即生效。城市缓存、方向核验证据、个人画像、运行和报告独立保存。所有配置保留并启用；明确检索接口可以暂无岗位，证据不足或请求失败也不自动停用。具体岗位仍核对类型及完整正文。详见 [共享架构与维护说明](ARCHITECTURE.md)。原 `build-recruitment-variants.mjs` 命令现仅刷新派生摘要，不再复制来源或覆盖 skill 文档。

校招全流程实测记录见 [冒烟报告](internet-campus-job-fit/artifacts/smoke-20260919/README.md)。下文为校招方向的详细说明。

## 校招岗位匹配

### 先遍历岗位，再判断适不适合你

只搜熟悉的公司和岗位名称，容易错过名称不同、实际职责却匹配的机会。统一流程从行业入选公司的公开招聘来源获取岗位，结合你的简历和偏好逐岗评估，不止返回一组关键词搜索结果。

- **遍历公司与岗位。** 对入选公司尝试读取公开来源的全部可访问分页，识别当次开放的正式校招岗位，减少逐个招聘站手动查找的工作。
- **支持范围内完整评估。** 选择全量模式后，逐一处理确认范围内的可评估岗位，不以推荐 Top N 或少量抽样代替全量工作。数量较多时分批并行，支持暂停和续跑。
- **每个岗位完整阅读。** 对照职责、任职要求和招聘条件，解释你的哪些经历能支撑岗位、哪些能力仍有缺口，不凭标题或关键词直接给结论。
- **同时看能力与意愿。** 先核对毕业届别和学历，再分别回答“我能否胜任”和“这个岗位是否符合我的需求”。有相关经历，不等于必须继续做同一行业或职能。
- **给出可行动的结果。** 用“可以投递／投递前准备／暂不建议投递”区分下一步，并提供匹配理由、主要缺口及官方岗位链接。
- **看得到完成范围。** 已评估、待核实、未评估和来源限制分别保留，不把读取失败解释成没有招聘，也不把尚未完成的任务当作全量完成。

这里的“完整”有明确边界：**对已收录来源中、用户确认范围内、当次能取得完整资料的正式校招岗位，逐一完成评估。** 它不代表已经抓到全市场所有公司、所有渠道的岗位，也不代表模型判断不会出错。

### 不只适合技术岗位

可以围绕研发、产品、运营、项目管理、设计、客户成功、销售、HR、财务等职能寻找机会，实际可评估岗位以当次来源为准。公司范围与岗位职能是两回事：同一家互联网公司里的通用职能，也会纳入确认范围后的评估。

你可以限定城市、公司、职能和业务偏好，也可以开放行业偏好，看看同一项能力还能迁移到哪些工作中。

### 怎么开始？

在支持本仓库 skill 及其运行依赖的 Agent 环境中，提供简历、毕业时间和求职倾向，用自然语言说明希望评估的范围。例如：

> 使用 `internet-campus-job-fit`。这是我的简历，我是 2027 届硕士，选择互联网和智能硬件，偏好上海的项目管理相关岗位。请先展示收录公司中的岗位覆盖情况，再帮我确认全量评估范围。

也可以直接明确范围：

> 使用 `internet-campus-job-fit`，选择互联网行业，评估腾讯、网易、米哈游当前公开的正式校招岗位。请完整阅读范围内的岗位，并给出投递建议。

实际流程是：选择行业 → 整理个人材料 → 展示公司与岗位范围 → 确认评估范围 → 逐岗全文评估 → 交付 Excel。已经明确过范围时直接沿用，不反复要求确认；只想先试一批也可以，不会未经同意扩大到全量。

### 最后会拿到什么？

一份 Excel 工作簿，包含四个工作表：

| 工作表 | 你可以看到什么 |
| --- | --- |
| 岗位匹配 | 公司、岗位、投递建议、匹配层级、城市、能力与意愿判断、届别学历条件、详细理由及 JD 链接 |
| 待核实与未评估 | 资料不完整或尚未完成评估的岗位，不混作有效推荐 |
| 公司简介 | 已保存的业务介绍、人数及融资／上市／注册资本资料，并保留资料时点与来源 |
| 来源覆盖 | 各公司获取范围、评估数量、资料待确认数量及覆盖限制 |

完整 JD 与内部证据对照另行归档，方便追溯；最终交付目录只保存报告文件。工具不会自动替你投递，也不会承诺面试或录用结果。

### 关于岗位时效与覆盖

岗位信息来自维护名单中的公开招聘 API，SAP 使用官方 RSS。首次采集获取当次资料，续跑可复用快照；需要最新岗位时明确要求刷新，报告保留资料日期。

未收录公司、接口未公开的岗位、登录后才可见的渠道，不在当前完整覆盖承诺内。分页受限、接口失败和招聘性质不明确时，会在结果中说明。例如 SAP 的 RSS 仅提供最新 10 条，始终按部分覆盖处理。选择全量评估不会消除这些来源限制。

## 使用与开发

每个 skill 在仓库根目录拥有独立文件夹；公共来源、公司事实及实现统一位于 `shared/job-search-core`，业务说明、方向配置及运行产物归属对应 skill。目录约定见 [AGENTS.md](AGENTS.md)。固定名单按上述行业维护，仅纳入已验证可读取完整 JD 的公开接口，也不按国企、私企或外企限制公司来源。新增 API 的成功记录有验证日期，不承诺接口永久在线；每次运行仍记录实际获取结果。

```text
job-search-skill-pack/
  README.md
  AGENTS.md
  ARCHITECTURE.md
  shared/job-search-core/   # 唯一来源库、公司事实、公共运行代码
  internet-campus-job-fit/  # 校招入口、规则、城市缓存、运行产物
  internship-job-fit/       # 实习入口、规则、城市缓存、运行产物
  social-job-fit/           # 社招入口、规则、城市缓存、运行产物
```

入口：[统一校招岗位匹配](internet-campus-job-fit/SKILL.md)。详细命令与数据格式：[运行与数据约定](internet-campus-job-fit/references/workflow.md)。

- Node.js 22+；采集与校验使用原生模块，无需额外 npm 安装。
- Python 3 用于简历文本提取及部分公开 API 采集；PDF 文本提取需要 `pypdf`。
- Excel 导出依赖 Codex 附带的 `@oai/artifact-tool`。通过 `load_workspace_dependencies` 定位依赖，必要时设置 `CODEX_NODE_MODULES`。

在仓库根目录执行本地检查（不启动岗位采集或评估）：

```sh
node --test internet-campus-job-fit/scripts/tests/*.test.mjs
node internet-campus-job-fit/scripts/campus.mjs status
```

统一入口继续使用 `internet-campus-job-fit` 名称，以兼容已存在的使用方式；界面显示为“校招岗位匹配”。报告文件名仍为 `校招岗位匹配.xlsx`。历史证据中的旧路径文本保留原样；定位迁移后的本地文件时使用新目录前缀，不将改名当成重新采集或重新核验。

## 数据与隐私

Git 跟踪源码、配置、参考文档及已维护的公司资料。个人简历、画像、匹配结果、原始抓取证据、日志和临时文件保留在对应 skill 的 `runs/`、`outputs/`、`artifacts/`、`tmp/` 等目录，由 `.gitignore` 排除，不随代码提交。

公司资料保留原有快照日期，改名不会刷新数据。历史维护脚本 `backfill-ownership-from-registry.mjs` 依赖本地调查产物，不随仓库分发；日常匹配复用 `data/` 中已保存的资料。
