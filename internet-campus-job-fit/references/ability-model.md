# 校招能力证据模型 v3

评估前阅读本文件，再按 assessment.md 写入评估。模型评价的是“现有材料对胜任该校招岗位的支持程度”，不是人格、潜力总分或录取概率。逐岗全文阅读，能力与意愿、资格分开。

## 1. 先分清材料在说什么

画像中的每条证据保留原文含义、来源与唯一 ID，区分三个轴：

| 轴 | 字段及用途 |
| --- | --- |
| 从哪里取得 | `kind`：resume / self_description / user_clarification；只表示来源，不代表客观性 |
| 说的是什么 | `claim_type`：objective_experience（客观经历）/ objective_achievement（客观成就）/ self_assessment（主观自评）/ preference（意愿） |
| 在什么情境发生 | `experience_type`：internship / employment / research_project / course_project / personal_project / other / none；同一段经历用同一 `experience_id` |

客观经历是具体任务、行动和责任，如“在电商实习中使用 A/B 测试分析促销券”；客观成就是具体产出或结果，如上线模块、论文作者顺序、竞赛获奖、已说明口径的改进指标。自评如“熟悉 Python”“沟通能力强”“学习能力突出”；意愿如“想做产品经理”。一条文字混合多类时拆开，保留共同经历 ID，不把自评混入事实。

“客观”指可核对的事实陈述，不表示 skill 已外部验证。简历和口述中有具体内容的事实都可以作为候选人报告的经历；附件、代码或证书实际看过才说明“已查看”。指标的估算口径、团队归属和未验证部分如实保留，不将自述百分比当作独立验证。

例：“在某公司实习，学习能力强，协助上线报表，团队 GMV 增长 20%”应拆出实习与报表行动、团队结果、自评；不能把团队 20% 全归个人，也不能仅因有数字就称强证据。

学历、课程、证书等事实可归 `other`，与其具体学习或认证记录共用经历 ID；它们对资格、基础知识的支持不自动等于做过核心工作。主观自评与意愿没有实践情境时为 `none`，`experience_id` 可为 null。

## 2. 经历的相对分量

采用用户确定的校招默认顺序：在对口程度和证据质量相近时，实习经历优先于学校／个人项目，再看其他相关经历；客观经历与成就的分量高于主观自评。这是本 skill 的判断约定，不是一个经过统计验证的统一权重公式。

- **对口实习**：分行业、部门业务、岗位职能三个维度判断，见下表。实际任务、方法、交付物与 JD 核心工作相近，是强关联信号。优先看做过什么、本人负责多少、持续深度和成果，而非公司名气或职位名称。
- **多段对口实习**：不同经历反复证明核心能力，或覆盖了更多核心环节时，增强匹配判断。多段浅层、重复或不对口经历不能抵消核心缺口。若均已达到高档，新增证据可增强理由的充分性，不必虚构更高等级。
- **高质量学校／个人项目**：看问题是否真实、个人贡献是否明确、方法是否有难度、产物是否完整、是否有测试／基线比较／用户反馈等验证。作品、独立实验、真实使用、论文及竞赛结果均可支持，不要求每个项目都有商业收入或量化收益。高质量且直接覆盖核心要求的项目可以评高；无实习不设等级上限。
- **其他相关经历**：社团、志愿服务、支教等按实际任务判断。对沟通、组织、教学等工作可能直接相关，不因类别靠后就一律评低；也不能用一般协作经历证明专项技术能力。
- **已有正式工作**：按真实工作责任、对口程度和结果评估，属于工作场景证据，不降为“其他经历”；是否满足校招资格另判。

先判断对口程度，再在可比证据间考虑经历层级、贡献与成果质量。高度对口的独立项目可以比不对口或只有头衔的实习更有说服力。学校／公司品牌不单独加能力等级。

同一次实习拆成三条证据仍是一段经历；同一个成果的不同写法也不能重复累计。不同证据可同时支持不同要求，但综合时按 `experience_id` 识别独立经历，并检查是否只是同一任务的重复描述。

### 对口实习的分层

行业是产品／服务所在的大领域；部门业务是实习团队面向的业务对象、场景和环节；岗位职能是本人实际承担的工作。三者分别记录 `same`（相同／高度一致）、`adjacent`（相邻／部分相关）、`different`（明显不同）、`unknown`（信息不足）。不能用公司主营业务推断所在部门，也不能用职位名证明本人做过哪些任务。

| 已有实习与目标 JD 的关系 | 能力判断如何使用 |
| --- | --- |
| 部门业务与岗位职能均高度对口，行业也相近 | 具有最直接的实践迁移基础；仍需核对本人行动、责任与成果，不凭分类自动评高 |
| 岗位职能对口，行业或部门业务不同 | 属于职能对口：如电商数据分析转到金融数据分析，方法可直接或部分迁移，业务指标与规则仍需核对 |
| 行业／部门业务对口，岗位职能不完全对口 | 属于业务对口：如游戏运营转游戏产品，业务理解、用户认识、协作经验有价值，产品设计与交付能力另找证据 |
| 只有行业相同，部门场景和实际任务差异很大 | 属于行业背景关联，支持有限；不能因为同在游戏公司就认定做财务与做玩法设计高度对口 |
| 三个维度都有距离，但有具体相通任务 | 保留可迁移能力，解释任务层面的联系；不能简单判为完全无关 |
| 信息不足 | 对相应维度标 unknown，只评价已知行动，不猜部门业务和岗位内容 |

同职能跨业务、同业务跨职能都属于有效的部分对口，不固定规定两者谁总是更高。技术／专业岗位通常要特别核对实际任务与方法，领域知识决定性更强的岗位则必须核对业务经验；依据具体 JD 的核心要求说明分量。

对口分层与证据强度分开：跨行业但相同职能的扎实经历可以是强证据；同业务、同岗位但只写“参与实习”仍是弱证据。单个维度 different 不会自动判低，也不会强制将整体能力限制为 medium：若业务差异仅影响一般要求，跨行业经历仍可能充分支持核心工作；若差异正是决定性核心，则体现为迁移支持或缺口。

每条评估为所引用的每段客观实习／工作经历填写一项 `experience_relevance`：`experience_id`、`industry_relation`、`business_relation`、`role_relation` 和 `explanation`。解释具体关联、事实依据及剩余差异；同一经历只写一次，避免多段证据重复增益。没有引用实习／工作时可省略或为空数组。程序只检查枚举与经历覆盖，不自动推断相似度或生成分数。

## 3. 按 JD 建立对照，而不是累计关键词

完整读完职责、要求、招聘证据后，先形成岗位标准，再找画像支持，避免为迁就简历改变标准。比较项覆盖主要职责和决定性要求：

| `requirement_type` | 处理 |
| --- | --- |
| core | 决定性核心能力：岗位的主要交付及缺失后不能胜任的能力；必须逐项覆盖，不能为评高而改标一般项 |
| supporting | 一般要求或可在岗补充的能力，记录缺口及影响 |
| bonus | 明确加分项；缺少不当作硬性不合格 |
| eligibility | 学历、毕业窗口、校招身份等资格；不用于抬高或降低能力等级 |

核心工作按校招生的责任水平判断，不擅自要求资深候选人的规模经验。多个可选方向只需按 JD 的选择关系评估；独立必须条件不能当成可选。

每项能力要求写明 `support`：direct（实际做过高度相近任务）、transferable（有具体迁移路径但情境／方法／责任存在差异）、unsupported（当前没有支持）。再评 `evidence_strength`：

| 强度 | 判断锚点 |
| --- | --- |
| strong | 客观行动与个人责任清楚，并有足以支撑该要求的产出、结果或完整实施细节；实习、工作及高质量项目均可达到 |
| moderate | 有具体客观实践或成就，但职责深度、验证、结果或归属仍有一部分不清楚 |
| weak | 只有头衔、参与描述、课程／工具罗列，或无实践支撑的主观自评；不能因“大厂实习”自动变强 |
| none | 没有可支持该项要求的材料；support 应为 unsupported |

强度是“对这项要求的证据质量”，不是经历的永久等级。同一经历可以强力证明分析，却只弱支持产品规划。`explanation` 要写个人动作与产物如何对应要求、本人贡献及边界；`gap` 写决定性缺口。不能只写“E3 相关”。

## 4. 合成能力等级

| 等级 | v3 判定 |
| --- | --- |
| high | 决定性核心要求均有直接客观支持（中或强），至少一项核心要求有强证据；剩余一般／加分项缺口不推翻主要工作胜任依据 |
| medium | 核心或一般能力要求有中／强的客观实践支持与明确迁移路径，但核心覆盖、责任深度或证据质量仍不足以评高；给出具体可迁移内容及缺口。仅弱头衔或加分项证书不够 |
| low | 已有材料足以比对，但主要工作要求缺少相应证据或关联很弱；用“未提供证据”，不把未写等同确定不会 |
| unknown | 材料过少、正文缺失或关键信息冲突，无法可靠区分上述等级，保留待评估 |

仅主观自评不能支撑 high 或 medium。有较完整简历但目标核心工作缺证可以 low；只有几句自评、无法了解实践背景则 unknown。明确的资格不符照样单独记录，不把有能力但超出毕业窗口的人写成能力低。

`ability_reason` 必填，解释三件事：最强依据来自哪几段实习／项目／其他经历；个人贡献与成果如何支撑核心要求，多段经历是否提供独立增量；哪些缺口决定了高、中或低。缺乏数值绩效不自动降级，成果质量也不能仅按数字大小比较。重复证据、主观赞美和不相关奖项不能通过数量补足核心能力缺口。

能力证据锚点在 v4 中保留；意愿、双向汇总与行动排序按 [双向匹配模型](reciprocal-model.md)，不要用毕业资格或业务偏好改写能力。

## 5. 校验和历史结果

评估使用 `assessment_version: 4`，同时写 `jd_fingerprint` 和 `profile_fingerprint`。`next-batch` 提供当前完整画像指纹；正文、画像事实／分类／偏好／测试标记或模型版本改变后，旧记录不得直接复用。旧记录必须重新阅读并评估，禁止只补版本、证据分类或指纹。

程序拒绝缺少分类、主观证据独撑高／中能力、强度与支持关系矛盾、核心缺口却评高等结构问题。它不会按实习次数或关键词打分，也不能证明模型确实读过、分类正确、经历真实或主要要求提取完整。运行通过仍须检查语义；不得把格式有效称为事实已验证。

## 6. 调研依据与适用边界

核对日期：2026-09-07。以下是一手材料；用于解释判断原则，不把海外雇主样本当成中国校招统一规则，也不把面试测评的效度等同于简历判断的准确率。

- [NACE：Internship Experience Often the Deciding Factor Between Equal Candidates](https://naceweb.org/talent-acquisition/candidate-selection/internship-experience-often-the-deciding-factor-between-equal-candidates)，2026-02-09，Job Outlook 2026 的 183 家雇主回答。其他条件相近时，本组织或同行业实习是重要区分因素。支持重视相关实习；未证明实习次数与录取概率线性相关，也未给出实习对项目的固定权重。
- [NACE：What Are Employers Looking for When Reviewing College Students’ Resumes?](https://naceweb.org/talent-acquisition/candidate-selection/cab48580-8599-4298-b695-d2e6b1b0e8d3)，2024-12-09，Job Outlook 2025。强调能否做工作的技能证据，以及课堂和实践活动中形成的能力。用于保留项目与其他经历的有效证据；不据此为用户编造软技能。
- [Amazon 招聘人员：Resume writing tips](https://www.aboutamazon.com/news/workplace/amazon-job-application-resume-writing-tips)，本次已读取原文，页面提取未显示发布日期。关注个人行动与结果，将成就对准目标岗位要求，并承认并非每条都能量化。用于检视任务、贡献、成果与归属；不复制示例数字或要求所有项目必须有收益数据。
- [CIPD：Selection methods](https://www.cipd.org/uk/knowledge/factsheets/selection-factsheet/)，2024-11-11。主张清晰一致的岗位标准、结构化评估和贴近实际工作的技能任务。用于建立要求分类与证据强度锚点；将已有项目类比为工作样本是本模型的应用推断，不等于实际组织过技能测验。

这里的经历默认顺序来自用户约定；高／中门槛、强度字段与版本校验是为该 skill 设计的实现规则，尚未用真实筛选／面试结果校准。后续迭代应使用经核对的岗位、画像和招聘反馈检查分档一致性。
