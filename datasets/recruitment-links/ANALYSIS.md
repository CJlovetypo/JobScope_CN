整理于 2026-09-22；数据来自本地历史文件，本轮未联网。可重算统计见 [index/summary.json](index/summary.json)，原始抓取时间与哈希见各快照和清单。

WPS 原报告的 **12,684** 是规范化 URL 去重数，本次 **12,797** 按 `url_original` 精确字符串去重，两种口径不混用。本次保留 9 条无效 URL 和所有重复出现记录。Waiqi 的 59,445 条岗位记录不等于招聘链接数：多个岗位可引用同一链接，也有岗位没有外部链接。上述数字不能称为“当前可投岗位”或“已验证有效链接”。

索引输入另保存 900 条历史 API 复核记录（飞书 198、WPS 702）及 884 条 Waiqi 接口目录记录。它们与正式配置有重叠，用于恢复参数和验证证据，不能累加成公司数。

## 可以直接用于修复的规律

### 1. 域名和门户相对稳定，项目／活动参数更容易变化

WPS 中 **1,530 个完全相同的公司名称**出现在多个届别，形成跨期检索入口；同名尚未做企业实体消歧。

| 样本 | 历史变化 | 修复含义 |
| --- | --- | --- |
| 腾讯 | 2025 秋表 `join.qq.com/post.html?query=p_1`；2026 秋表同路径另有 `activity=1193279687157891072` | 先返回官方招聘门户确认当前活动，不从旧活动 ID 猜新值 |
| 字节跳动 | 2025 春表 campus/position 的 `project=7468181288324794631`，2026 春表为 `7525009396952582407` | 公司、校园路径稳定，但项目需从当期官方配置重取，不能直接改年份 |
| 比亚迪 | 2025 春表为 `job.byd.com/portal/pc/#/school/schoolSangfor?...`；2026 春表为 `https://job.byd.com/` | hash 路由承载专题信息；根站可作调查入口，不能当作原岗位的新链接 |

证据：冻结的 [wps-links.csv](snapshots/2026-09-22/wps-links.csv)，对应 CSV 数据记录腾讯 793／7283，字节 3512／8773，比亚迪 3700／10445。记录编号不是文本行号。这里展示关键参数，完整原始 URL 均留在数据集中。

### 2. 公告、表格文本和招聘入口应连起来查

WPS 的 15,935 条记录中，9,461 条为微信公众号链接（约 59.4%）。历史提取还发现 **60 条纯文本 URL**，它们并非 WPS 超链接对象。仅按可点击单元格抽取会漏掉这一类；只保存 ATS 租户也会丢掉官方公告和二维码线索。

应按“同文档、同工作表、同行”同时读公司名、公告列和投递列；公告实际链接／二维码／二跳才是下一步候选，不能从文章标题臆造官网。证据：[WPS 扩容报告](collections/wps-campus-sources-20260919/扩容报告.md) 与原始 CSV 的 `source_kind`、`row`、`column`。

### 3. 可抓到完整 JD 仍可能修错公司

WPS 深度复核明确排除了 **9 个技术可读但雇主不符或无法安全归并的配置**。例如天津创业环保的 51job 入口指向天津低空经济投资发展，麦格纳中国入口指向赫基集团。主体关系需要官方证据，不能因为集团、拼写或平台相似就采用。

证据：[主体不符清单](collections/wps-campus-sources-20260919/deep-api-review/主体不符未准入.csv)、[深度复核报告](collections/wps-campus-sources-20260919/deep-api-review/深度API复核报告.md)。这些是 2026-09-19 的历史复核结论，未来关系变化需重新确认。

### 4. “未发现接口”经常只是发现路径不完整

第四轮复核恢复了惠科、住建部招聘平台、UPM 三条数据通路：前两者依赖职位相关的懒加载模块，UPM 依赖官网后续跳转到 Workday。惠科同源 `/admin/homepage/positions` 路由也曾被过窄的 API 规则漏掉。

实用办法是跟踪真实职位页和已引用模块，核对 HTTP 方法及请求体；同时记录扫描预算和未读范围。发现成本增加后取得更多结果，不代表网站恰好新增了接口。证据：[第四轮闭环复核报告](collections/wps-campus-sources-20260919/deep-api-review/第四轮闭环复核报告.md)。

### 5. 链接存在、列表可用、JD 完整、当前开放是四件事

Waiqi 接口快照 884 条中有 693 条 `unverified_candidate`、62 条 `entrance_only`、83 条 `registered_source`，其余仍包含待核主体、待核范围或部分列表。目录返回公司的岗位计数也曾与真实岗位列表不一致。

因此修复结果必须分层：当前官方入口 → 正确主体列表 → 特定岗位完整 JD → 当前开放状态。修好入口不等于恢复全部采集能力，结构正确的空列表不等于链接坏了。详见 [Waiqi 维护说明](../../shared/job-search-core/references/waiqi-sources.md) 与冻结的 [接口目录](snapshots/2026-09-22/waiqi-interfaces.json)。

## 建议的处理顺序

1. 查同公司历史链接和已验证请求，保留 URL 中的频道、项目、组织及地区参数。
2. 区分网络／访问限制、岗位结束、正常空列表与真正的入口或契约变化。
3. 沿当前官网、实际跳转或公开前端配置提出少量候选。
4. 重验雇主、招聘方向、地区、列表分页和完整 JD；冲突时不给出伪修复。
5. 在用户要求的范围内应用已验证变更，保存旧配置并重新运行原查询；新证据追加为新批次。

可执行流程和各平台注意事项已整理到 [recruitment-link-repair](../../recruitment-link-repair/SKILL.md)。

## 整理验收

- 六个原始目录完整迁入 `collections`，旧目录通过联接兼容；清单记录 111,558 个文件、13,389,227,320 字节（约 12.47 GiB）。该数字包括过程文件及备份，不是独立招聘数据条数。
- 12 份冻结输入和 2 个索引的 SHA256 核对通过；WPS CSV 用独立 Python CSV 解析复核，15,935 行及原始 URL、公司、坐标完全一致。
- 96,067 个观察 ID 无重复；全部 101,499 个观察／契约证据指针可定位到冻结输入。
- 查询工具 3 项行为测试通过，覆盖 CSV 换行和引号、URL 路由、域名边界、证据重复保留、截断提示及不升级可用性状态；skill 格式验证通过。
- 原件全文件清单中 67,698 份已计算哈希，43,860 份仅保留大小和修改时间，未宣称全部原件完成内容校验。其他进程更新产生的变化单独记录在清单摘要中。
