# 公司简介资料库

`../../../shared/job-search-core/data/company-profiles.json` 是跨运行复用的资料库，以 `../../../shared/job-search-core/assets/sources.json` 的固定 `company_id` 关联，不按展示名称模糊匹配。日常 `prepare` 和 `render` 均只读本地资料，不发网络请求。资料与个人能力、意愿评分独立。

## 维护

在 skill 根目录执行：

```bash
node scripts/company-profiles.mjs sync
node scripts/company-profiles.mjs status
node scripts/company-profiles.mjs import tmp/company-profiles-research/reviewed.json
```

`sync` 为固定名单补建记录，并复用已有、有完整证据的业务简介；保留已有的各字段资料。`status` 只读并列出缺口。仅在主动维护任务中，针对新增公司、补缺或明确更新需求，agent 定向查阅官方介绍、年报、公司公告或公开工商材料，真实阅读后写补充 JSON 再 `import`。导出阶段不承担调研。部分记录缺资料可以继续匹配与交付，不把本任务变成每轮全公司重查。

补充文件是 `{ "companies": [...] }`。每项含 `company_id`，以及本次更新的 `business`、`workforce`、`capital` 中一个或多个字段；未提供字段不覆盖原值。每个字段结构：

```json
{
  "value": "截至2025年12月31日，集团共有约1,200名员工。",
  "status": "verified",
  "entity": "示例集团（全球合并口径）",
  "as_of": "2025-12-31",
  "checked_at": "2026-09-13",
  "evidence": [{"url": "https://example.com/annual-report", "title": "示例年报", "note": "仅结构示例，不得作为真实公司证据。"}]
}
```

- `verified`：已有真实可读依据。内容、主体、核实日期和来源 URL／标题／具体依据必填；统计日期有则填写，无则留空，不能把核实日期冒充统计日期。
- `missing`：尚无已核实资料，`value` 为空；Excel 展示“暂无已核实资料”。不表示未公开、未融资、没有员工或数字为零。
- `not_disclosed`：实际核对过资料后确认该资料未披露相应指标，仍须保存核查来源、范围和日期。不要据单页缺字段声称全网未披露。

业务简介优先复用 `company-business-tags.json` 中有依据的一句话介绍；旧业务索引为 unknown 的公司保留缺项，主动维护时再补证据，不凭名字编写。人数允许官方披露的区间或约数；明确区分集团全球人数、国内人数、用人主体人数与参保人数。不得把参保人数直接当作整个集团人数。

资本信息可以包含已核实的融资事件、上市情况或具体主体注册资本。历史融资写事件时间，不能未经更新就称“最新轮次”。注册资本须带币种、单位与法律主体，不等于融资额、估值、营业收入或现金余额。母子公司不得混写；上市地不用于推断公司性质。

同一字段多份来源可以并存，保留 URL 原样；资料时点与口径随内容在 Excel 中展示。内部证据摘录、核查方法和历史缺口只进 JSON。调研原始文件放 `tmp/` 或 `artifacts/`，不可让日常生成依赖临时目录。

## 深度复核与增量补充

明确要求深度调研时，逐家公司建立复核记录，再合并通过检查的字段。不能仅把旧简介迁移为新格式，或只研究头部公司后宣称全量完成。全量复核表示每家公司有实际检索及可追溯记录，不表示每个字段均有可靠公开数据，更不表示历史数字已经更新到当前。

1. 优先读取公司官网、投资者关系页、交易所年报／招股书、投资方公告、公开工商材料和公司提供给高校的招聘原文。搜索摘要仅用于定位资料；须打开正文核对数字、表头、日期及主体。确需原创媒体报道时，在证据内标记 `source_tier: "secondary"`，并保留记者确认对象及上下文；公司原始披露标记 `primary`，镜像托管须写明。
2. 人数须检查母子公司合计及分项之和，区分期末在职、全年领薪、全职／兼职、派遣、平台司机、服务商、师资网络及参保人数。PDF 抽取有矛盾时回看原始页面；原文仍矛盾则暂不采纳，不自行算出一个数替代正式披露。
3. `as_of` 只记录原文明确的统计或事件日期。招聘发布日期、网页更新时间与核实日期不能冒充人数截止日；可在内容中写“2025年招聘资料披露”并让 `as_of` 留空。旧年报或旧融资可以保留，但必须呈现历史时间，不能称为当前或最新。
4. 资本信息区分融资总额、单个投资方投入、估值、注册资本、上市募资总额／净额及并购交易对价。上市申请、计划融资或拟收购不写成已完成；更名、退市、业务分拆及母公司关系须核对，不能将母公司的属性无说明地赋给子公司。
5. 每家公司保存查询字段、实际访问来源、读取结果、采纳理由、未决字段及未采用原因。访问失败、搜索摘要未读、主体歧义和原表冲突分开记录；这些情况均不等于“未公开”。审阅后通过 `import` 增量合并，保留未更新字段和更新前备份。

每批复核目录建议包含 `before.json`、`patch-*.json`、`review-*.json`、合并补丁、前后覆盖统计及简短复核报告。报告中的覆盖率按 `business`／`workforce`／`capital` 分别计算；资本有股票代码不代表已获得融资金额，人数有历史数据不代表已获得最新数据。日常生成仍只使用正式资料库，不重跑本节流程。

## 运行和交付

`prepare` 保存 `runs/<运行>/company-profiles.snapshot.json`；旧运行首次 `render` 时从资料库补存。之后重复导出优先使用该快照，不静默改变旧报告。资料更新后如需用于报告，新建运行；若用户明确要求仅刷新某运行的公司简介，先在该运行内保存旧快照副本，再换入经核验的新快照，不改岗位评估。

“公司简介”覆盖本工作簿全部公司，按 ID 去重，每家三行，缺失资料也保留该行。“来源覆盖”中的城市排除、失败及暂无岗位公司同样入简介；不能只根据已评估岗位收集公司，造成漏项。空公司范围也保留页签和列头。

每次导出的 `logs/render-<时间戳>.json` 保存原说明表、详细来源覆盖、可选资料复核、画像和配置、资料快照与缺口；`report-audit.json` 指向最近一次日志。交付目录只存最终 Excel。日志不是 Excel 的隐藏附件，也不嵌入文档元数据。
